OpenClaiming Protocol

A minimal, cryptographically verifiable claim format for authorization and delegation. OCP claims are self-contained JSON objects signed with Ed25519 — no blockchain, no central authority, no server round-trip to verify.

§1 Core Claim Format

An OCP claim is a JSON object. Fields are defined below. All fields are optional unless marked required.

FieldTypeRequiredDescription
ocpintegeryesProtocol version. Must be 1 for this spec.
issstringyesIssuer key URI (see §5). Identifies the signing key.
substringnoSubject. The entity the claim is about (e.g. a publisher ID, a user ID, a domain).
stmobjectnoStatements. Arbitrary key-value claims about the subject. Schema is defined per claim type.
nbfintegernoNot before — Unix timestamp (seconds). Claim is invalid before this time.
expintegernoExpiry — Unix timestamp (seconds). 0 or absent means no expiry.
sigstringyesSignature — lowercase hex. See §3.

Minimal example

{
  "ocp": 1,
  "iss": "data:key/ed25519;hex,4a7f3c8d1b5e9f2a6c0e4d8b3f7a1c5e9d2b6e0a4c8f3d7b1e5a9c2f6d0b4e8a",
  "sub": "apps.example.com",
  "stm": { "publisherId": "apps.example.com", "rootCid": "bafyreid…" },
  "nbf": 1762000000,
  "exp": 1793536000,
  "sig": "3f2a…c8d1"
}
Note: Claims must be treated as untrusted input until sig is verified. Never rely on any field value before completing §4.

§2 Canonicalization

Before signing or verifying, the claim is canonicalized into a deterministic byte string:

  1. Remove the sig field.
  2. Sort the remaining top-level keys alphabetically (lexicographic, ascending).
  3. Serialize as JSON with no extra whitespace (JSON.stringify defaults). The serialization must be valid UTF-8.
// JavaScript reference
function canonicalize(claim) {
    const unsigned = { ...claim };
    delete unsigned.sig;
    const keys = Object.keys(unsigned).sort();
    const out = {};
    for (const k of keys) out[k] = unsigned[k];
    return JSON.stringify(out);   // → UTF-8 string
}
Nested objects inside stm are not recursively sorted — only the top-level keys of the claim are sorted. This keeps the canonicalization simple and allows arbitrary statement schemas.

§3 Signatures

Algorithm

OCP v1 uses Ed25519 signatures over a SHA-256 hash of the canonical form:

sig = Ed25519Sign(privKey, SHA-256(canonicalize(claim)))

SHA-256 is applied before Ed25519 for two reasons: it bounds the message length to 32 bytes (enabling hardware security keys that only sign fixed-length payloads), and it allows batch verification over arbitrary-length claims with a single hash call.

Encoding

  • Signature (sig): 64 raw bytes encoded as 128 lowercase hex characters.
  • Public key: 32 raw bytes encoded as 64 lowercase hex characters. Embedded in iss (see §5).
  • Private key: 32-byte Ed25519 scalar (the seed). Never included in a claim.

Signing (reference)

// Node.js
const hash = crypto.createHash('sha256').update(canon, 'utf8').digest();
const sig  = crypto.sign(null, hash, privKey).toString('hex');

// Browser (Web Crypto)
const hash = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(canon));
const sig  = await crypto.subtle.sign({ name: 'Ed25519' }, privKey, hash);

§4 Verification Algorithm

A verifier must execute these steps in order and reject the claim at the first failure:

  1. Parse. Decode the claim as JSON. Reject if malformed.
  2. Version check. Reject if claim.ocp !== 1.
  3. Required fields. Reject if iss or sig are absent or empty.
  4. Parse issuer. Extract the public key from iss per §5. Reject if the URI format is unrecognized.
  5. Temporal check. Reject if nbf is set and nbf > now + 300 (5-minute clock skew tolerance). Reject if exp is set and exp < now.
  6. Canonicalize. Apply §2 to produce the canonical string.
  7. Hash. Compute SHA-256(canonical).
  8. Verify signature. Verify sig against the hash using the issuer's public key per §3. Reject if invalid.
  9. Accept. The claim is valid. The verifier may now trust the contents of sub and stm.
Important: Step 8 must succeed before the verifier relies on any field — including iss, sub, and stm.

§5 Issuer Key URIs

The iss field is a URI that identifies the signing key. OCP v1 defines one URI form:

data:key/ed25519;hex,<64 lowercase hex chars>

Example:

data:key/ed25519;hex,4a7f3c8d1b5e9f2a6c0e4d8b3f7a1c5e9d2b6e0a4c8f3d7b1e5a9c2f6d0b4e8a

Future versions of this spec may define additional URI forms (e.g. DID URIs, HTTPS key endpoints). Verifiers must reject claims whose iss they do not recognize.

§6 Standard Statement Types

The stm object is extensible. OCP v1 defines the following standard statement schemas:

Publisher cert (stm.publisherId)

Authorizes a named publisher to serve content on behalf of the issuing author.

FieldTypeDescription
publisherIdstringDomain or identifier of the authorized publisher.
rootCidstring?Content root CID this cert covers. Absent = all roots for this author.
notesstring?Human-readable note (e.g. "distribution agreement 2026").

The sub field should equal stm.publisherId.

Delegate claim (stm.delegate)

Grants a delegate key the right to sign claims on behalf of the issuer, optionally scoped to specific statement types.

FieldTypeDescription
delegatestringKey URI of the delegate (same format as iss).
scopestring[]?Allowed statement types. Absent = unrestricted.

§7 Reference Implementations

Official reference libraries implement the full §4 verification algorithm and the §3 signing helpers.

LanguageFileRequirements
JavaScriptocp.jsBrowser (SubtleCrypto) or Node.js 15+ — zero runtime deps

JavaScript — verify

import OCP from './ocp.js';

const claim = {
    ocp: 1,
    iss: 'data:key/ed25519;hex,' + pubKeyHex,
    sub: 'apps.example.com',
    stm: { publisherId: 'apps.example.com' },
    nbf: Math.floor(Date.now() / 1000),
    exp: Math.floor(Date.now() / 1000) + 86400 * 365,
    sig: sigHex
};

const result = await OCP.verify(claim);
if (!result.ok) {
    console.error(result.error);  // 'OCP: signature verification failed' etc.
} else {
    console.log(result.pub);   // issuer pub key hex
    console.log(result.sub);   // 'apps.example.com'
    console.log(result.stm);   // { publisherId: … }
}

JavaScript — sign

const claim = await OCP.sign({
    iss: 'data:key/ed25519;hex,' + pubKeyHex,
    sub: 'apps.example.com',
    stm: { publisherId: 'apps.example.com', rootCid: 'bafyreid…' },
    nbf: Math.floor(Date.now() / 1000),
    exp: Math.floor(Date.now() / 1000) + 86400 * 365,
}, privKeyHex);
// claim.sig is now set

PHP — verify

require_once 'ocp.php';

$json  = $_POST['claim'] ?? '';
$result = OCP::verify($json);
if (!$result['ok']) {
    http_response_code(403);
    echo $result['error'];
    exit;
}
// $result['pub']  → issuer pub key hex
// $result['sub']  → subject
// $result['stm']  → statements array

PHP — publisher cert helper

$result = OCP::verifyPublisherCert($claimJson, 'apps.example.com', $rootCid);
if (!$result['ok']) {
    // publisher not authorized for this content
}
