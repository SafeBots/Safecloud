Streams Access Model

Safecloud 4.0 · classes/Safecloud/Streams.js

Overview

Every stream carries three integer thresholds — readLevel, writeLevel, adminLevel — that define what the general public can do without a specific grant. Per-user grants in the access table layer on top. For folder hierarchies, a stream can inherit its parent's access via the inheritAccess JSON field, optionally capped per axis.

All three systems compose by taking the maximum: a user's effective level on any axis is the highest level granted by any applicable source.

Access calculation

calculateAccess(byUserId, stream) is the single source of truth. It runs synchronously (better-sqlite3) and returns { readLevel, writeLevel, adminLevel }.

Algorithm

  1. Publisher shortcut. If byUserId === stream.publisherId, return { 40, 40, 40 } immediately.
  2. Stream defaults. Start with rl = stream.readLevel, wl = stream.writeLevel, al = stream.adminLevel.
  3. Direct access row. Query access table for ofUserId = byUserId. For each matching row, rl = max(rl, row.readLevel), and so on per axis.
  4. inheritAccess chain. Parse stream.inheritAccess (JSON array). For each entry [parentPub, parentName, [rlCap, wlCap, alCap]], recursively call calculateAccess on the parent stream, apply the caps, then rl = max(rl, min(parent.readLevel, rlCap)), etc. Caps default to 40 when omitted.

Cycle detection: a visited-key map (by publisherId + streamName) ensures circular inheritance returns { 0, 0, 0 } for the cycle node rather than looping.

// Example — compute effective access for a user on a doc stream
var Streams = require('./Safecloud/Streams');
var stream  = /* stream row from DB */;
var access  = Streams.calculateAccess('user-alice', stream);
// access = { readLevel: 35, writeLevel: 20, adminLevel: 15 }

inheritAccess — folder → file access cascade

When a file stream is put into a folder, the client may request that access on the folder cascade into the file. This is stored as an array of entries in the file stream's inheritAccess JSON column.

Schema of an inheritAccess entry

[parentPublisherId, parentStreamName]
// or with per-axis caps:
[parentPublisherId, parentStreamName, [readLevelCap, writeLevelCap, adminLevelCap]]

A cap of 40 (or omitting the caps array entirely) imposes no restriction. A cap of 23 on the write axis means: even if the caller has edit(30) on the parent folder, they only inherit up to content(23) on this file.

How it works in practice

Alice has readLevel=35, writeLevel=20 on the folder docs/files-finance. The file docs/file-q3-report has inheritAccess = [["pub", "docs/files-finance"]]. When calculateAccess("alice", fileStream) runs, it fetches the folder stream, calls calculateAccess on it (getting 35/20/0), applies default caps (40/40/40), and takes the max with the file's own defaults. Alice ends up with read=35, write=20 on the file without needing a direct access row on it.

Direct rows always win over inheritance. If Alice has a direct access row on the file granting her readLevel=10 (teaser only), the max of 10 and 35 (inherited) gives 35 — inheritance still wins here because we MAX. The only way to restrict a user below what inheritance would give is to remove them from the parent's access entirely and not add an inheritAccess entry.

Multiple parents

A file can inherit from multiple folders simultaneously (e.g. it's bookmarked in two places). Each entry in the array is resolved independently and the per-axis maxes are accumulated.

Capping inherited write access

A common pattern: a folder grants editors writeLevel=30 (edit), but you want folder members to have only post(20) on a pinned file they should comment on but not restructure:

inheritAccess = [["pub", "docs/files-finance", [40, 20, 0]]]
// read: uncapped (40) → inherits up to folder's readLevel
// write: capped at post(20)
// admin: capped at 0 → no admin inheritance at all

Routes

All routes are mounted at both /Streams/… and /action.php/Streams/…. byUserId is taken from the X-User-Id header, ?byUserId= query param, or POST body — in that priority order.

Core routes

GET /Streams/stream readLevel ≥ see (10)

Returns stream metadata. Fields are stripped above the caller's read level: content requires content(23); attributes requires fields(25); participant counts require participants(30). Returns 404 (not 403) when readLevel < see(10) to avoid leaking stream existence.

Response includes an access object with the caller's computed { readLevel, writeLevel, adminLevel }.

POST /Streams/stream open (any authenticated user)

Creates a stream. The creator (byUserId) is automatically granted a direct access row of 40/40/40 in the access table, unless they are already the stream's publisherId (which grants full access implicitly).

Body fields: publisherId, name, type, title, content, attributes, readLevel, writeLevel, adminLevel. ACL defaults follow the values in Default values below when omitted.

POST /Streams/message writeLevel ≥ post (20)

Appends a message. Requires writeLevel ≥ 20 on the target stream. Body: publisherId, streamName, type, content, idempotencyKey (optional UUID for exactly-once delivery).

GET /Streams/message readLevel ≥ messages (35)

Fetch a single message (?ordinal=N) or a range (?min=&max=&limit=&ascending=). Requires readLevel ≥ 35.

GET /Streams/messages readLevel ≥ messages (35)

Pull-replication alias. Accepts ?after=N&limit=L. Same access gate as /message.

POST /Streams/subscribe writeLevel ≥ join (10)

Become a participant and subscribe to push notifications. Requires writeLevel ≥ 10.

PATCH /Streams/stream writeLevel ≥ edit (30) for content adminLevel ≥ manage (30) for ACLs

Update a stream in place. Content fields (title, content, attributes) require writeLevel ≥ 30. ACL fields (readLevel, writeLevel, adminLevel, inheritAccess) require adminLevel ≥ 30. Both checks run if both kinds of fields are present.

Access management

GET /Streams/access adminLevel ≥ invite (20)

List all direct access rows for a stream. Query: ?publisherId=&streamName=.

POST /Streams/access adminLevel ≥ invite (20)

Grant a direct access row to ofUserId. The granting user cannot issue a level higher than their own on any axis — the server takes min(requested, grantor's level) silently.

Body: { publisherId, streamName, ofUserId, readLevel, writeLevel, adminLevel }. Upserts (updates if row already exists).

DELETE /Streams/access adminLevel ≥ invite (20)

Revoke a user's direct access row. Body: { publisherId, streamName, ofUserId }. Returns 404 if no row exists. After revocation, the user falls back to public stream defaults and any inheritAccess cascade.

Relate — putting files in folders

POST /Streams/relate writeLevel ≥ relate (23) on child

Relates a child stream (the file) to a parent stream (the folder). The key optional field is inheritAccess — when truthy, the parent's coordinates are appended to the child's inheritAccess JSON array, so anyone with access to the folder automatically cascades that access down to this file.

Body:

{
  "publisherId":   "alice",           // child stream's publisher
  "streamName":    "docs/file-q3",    // child stream
  "toPublisherId": "alice",           // parent (folder) publisher
  "toStreamName":  "docs/files-finance",
  "inheritAccess": true,              // checkbox — cascade parent access
  "caps":          [40, 20, 0]        // optional per-axis caps [read, write, admin]
                                      // 40 = uncapped; 0 = no inheritance on that axis
}

Also posts a Streams/relate message on the child stream so the relation appears in the message log and can be subscribed to. If the same parent is already listed in inheritAccess, the entry is replaced (not duplicated).

DELETE /Streams/relate adminLevel ≥ manage (30) on child

Removes a specific entry from the child stream's inheritAccess array. Body: { publisherId, streamName, toPublisherId, toStreamName }. Returns 404 if the entry does not exist.

Examples

Google Suite parity — doc sharing

Bob wants to share a doc with Carol as an editor and Dave as a viewer.

// 1. Grant Carol edit access
POST /Streams/access
{ "publisherId": "bob", "streamName": "docs/file-proposal",
  "ofUserId": "carol", "readLevel": 35, "writeLevel": 30, "adminLevel": 0 }

// 2. Grant Dave read access
POST /Streams/access
{ "publisherId": "bob", "streamName": "docs/file-proposal",
  "ofUserId": "dave", "readLevel": 35, "writeLevel": 0, "adminLevel": 0 }

// 3. Revoke Dave later
DELETE /Streams/access
{ "publisherId": "bob", "streamName": "docs/file-proposal", "ofUserId": "dave" }

Folder access cascade

Bob creates a finance folder and puts the Q3 report into it, inheriting access.

// 1. Grant Carol editor access on the folder
POST /Streams/access
{ "publisherId": "bob", "streamName": "docs/files-finance",
  "ofUserId": "carol", "readLevel": 35, "writeLevel": 30, "adminLevel": 15 }

// 2. Put the file in the folder and inherit access (the checkbox)
POST /Streams/relate
{ "publisherId":   "bob",
  "streamName":    "docs/file-q3",
  "toPublisherId": "bob",
  "toStreamName":  "docs/files-finance",
  "inheritAccess": true }

// Carol can now read and edit docs/file-q3 without an explicit row on it.
// If Bob later removes the relate entry, Carol loses that cascaded access.

Read access on a private stream

// Create a private doc (no public read)
POST /Streams/stream
{ "publisherId": "alice", "name": "docs/diary",
  "readLevel": 0, "writeLevel": 0, "adminLevel": 0 }

// GET /Streams/stream?publisherId=alice&streamName=docs/diary
// → 404 for everyone except alice (the publisher)
// alice gets 40/40/40 from the publisher shortcut, sees the stream normally.

Default values

When creating a stream without specifying ACL levels, the server applies these defaults. They match the convention in Qbix Streams:

FieldDefaultMeaning
readLevel40Public read — anyone can read messages.
writeLevel10Public join — anyone can subscribe/join.
adminLevel20Invite only — only people with an access row at invite(20)+ can manage invites.

For a private document (a draft, a private folder), set readLevel=0, writeLevel=0, adminLevel=0 at creation. The creating user gets a direct access row of 40/40/40 regardless.

Migration note. Existing streams created before this access layer was enforced have readLevel=40 (public) by default and will continue to behave as before — they are open to anyone. No migration is needed; the enforcement is additive.
